# Project Planning Skill

Use this skill to create `TASKS.md` — the implementation task list for the Software Engineer.

## When to Use

- Before the Software Engineer starts coding on a new or existing project
- When given an architecture document to decompose into actionable tasks
- When creating a recoverable, step-by-step implementation plan in GitHub

## Core Principle

**Each task must fit in a single focused agent context.**

A task is too large if it requires reading more than 3 files or writing more than 5 files.
A task is too small if it is a single function or configuration line.
The sweet spot: one logical unit of work that results in a testable, committable change.

---

## Planning Process

### Step 1 — Read the Architecture
Read and understand the full architecture document:
- Tech stack (Next.js vs React vs HTML/CSS/JS)
- File structure specified
- Database schema (if Supabase)
- Environment variables required
- All features listed

### Step 2 — Identify Logical Units
Group the work into logical units. Common groupings:

**For Next.js / React projects:**
1. Project initialization (package.json, config files, tsconfig)
2. Supabase/database client setup (lib/supabase.ts, .env.example)
3. Root layout + global styles (app/layout.tsx, app/globals.css)
4. One task per major page or feature component group
5. API routes (one task per route group)
6. README (always last)

> **Note:** Do NOT include database migrations or schema creation as a task.
> Migrations are handled separately by the Database Engineer before the Software Engineer starts.

**For HTML/CSS/JS projects:**
1. HTML structure (index.html)
2. CSS styling (css/styles.css)
3. JavaScript behavior (js/script.js)
4. README (always last)

**For existing projects (updates):**
1. One task per changed feature or file group
2. Keep tasks independent wherever possible

### Step 3 — Order the Tasks
Order tasks so that:
- Dependencies come before dependents (e.g., Supabase client before pages that use it)
- Configuration comes before implementation
- README is always the LAST task
- No task depends on a future task

### Step 4 — Write TASKS.md

Write the file to the GitHub repo root using `create_or_update_file`:

```
Owner: {github_owner}
Repo: {github_repo}
Path: TASKS.md
Branch: main
Commit message: "chore: add implementation task list"
```

---

## TASKS.md Format (use EXACTLY this format)

```markdown
# {Project Name} — Task List

> **Stack:** {tech_stack} | **Repo:** https://github.com/{owner}/{repo}
> Generated by Lead Engineer | Status: In Progress

---

## Tasks

- [ ] **Task 1: {Short Title}**
  {One to three sentences describing exactly what files to create/modify and what they should contain. Be specific about file paths.}

- [ ] **Task 2: {Short Title}**
  {Description}

- [ ] **Task 3: {Short Title}**
  {Description}

...

- [ ] **Task N: Write README**
  Create a comprehensive README.md at the repository root. Include: project title, live demo placeholder, features list, tech stack table, project structure tree, database schema (if Supabase), environment variables table, getting started steps, deployment instructions, and MIT license. Commit with message: `docs: add comprehensive README`.
```

---

## Task Writing Rules

### DO:
- Use **specific file paths** in every task description: `Create app/page.tsx`, `Create components/Header.tsx`
- Include the **commit message** for each task: `feat: add <filename>`
- List all files a task creates in a single clear sentence
- Mark the README task as always last

### DO NOT:
- Write tasks like "implement the frontend" — too vague, too large
- Include more than 5 files per task
- Create tasks that depend on knowledge from later tasks
- Skip the README task
- **Include ANY database migration tasks** — `supabase/migrations/*.sql`, schema creation, `CREATE TABLE` scripts, or any Supabase migration steps. These are run by the Database Engineer in a separate step before the Software Engineer begins. The Software Engineer only writes application code on top of an already-existing schema.

---

## Task Count Guidelines

| Project Type | Recommended Task Count |
|---|---|
| Simple HTML/CSS/JS | 4–6 tasks |
| React/Vite SPA | 7–10 tasks |
| Next.js full-stack | 10–15 tasks |
| Existing project update | 3–8 tasks |

## Example TASKS.md (Next.js + Supabase)

```markdown
# Portfolio Dashboard — Task List

> **Stack:** Next.js 14, TypeScript, Tailwind CSS, Supabase | **Repo:** https://github.com/user/portfolio-dashboard
> Generated by Lead Engineer | Status: In Progress

---

## Tasks

- [ ] **Task 1: Initialize Next.js project**
  Create package.json (next, react, react-dom, typescript, tailwindcss, @supabase/supabase-js), next.config.ts, tsconfig.json, and .gitignore. Commit: `chore: initialize Next.js project`.

- [ ] **Task 2: Configure Tailwind CSS**
  Create tailwind.config.ts and postcss.config.js. Commit: `chore: add Tailwind CSS config`.

- [ ] **Task 3: Set up Supabase client**
  Create lib/supabase.ts with createClient helper using env vars. Create .env.example listing NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY. Commit: `chore: add Supabase client`.

- [ ] **Task 4: Create root layout and global styles**
  Create app/layout.tsx (metadata, fonts, global CSS import) and app/globals.css (Tailwind directives + custom properties). Commit: `feat: add root layout`.

- [ ] **Task 5: Build home page**
  Create app/page.tsx implementing the Hero, Features, and CTA sections from the architecture. Commit: `feat: add home page`.

- [ ] **Task 6: Build dashboard page**
  Create app/dashboard/page.tsx and app/dashboard/layout.tsx with the sidebar navigation and stats cards. Commit: `feat: add dashboard page`.

- [ ] **Task 7: Create shared components**
  Create components/Header.tsx, components/Footer.tsx, and components/Button.tsx. Commit: `feat: add shared components`.

- [ ] **Task 8: Add Supabase API route**
  Create app/api/projects/route.ts with GET and POST handlers using the Supabase service role client. Commit: `feat: add projects API route`.

- [ ] **Task 9: Write README**
  Create comprehensive README.md at the repository root per the README Specification in the architecture document. Commit: `docs: add comprehensive README`.
```

## Output After Writing TASKS.md

Confirm completion:

```
## Planning Complete

TASKS.md written to: https://github.com/{owner}/{repo}/blob/main/TASKS.md

Task breakdown ({N} tasks):
1. Initialize Next.js project
2. Configure Tailwind CSS
...
N. Write README

The Software Engineer will execute these tasks one at a time, marking each [x] when complete.
```
